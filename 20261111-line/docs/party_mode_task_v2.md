# 任務 v2：以新六位角色取代聚會模式角色，並補強品質控制

本文件取代 `party_mode_task.md`。舊版假設「六個角色在同一次呼叫」，與實際不符，請以本文件為準。

## 使用者已做的決定（覆蓋先前規定）
- 使用者**明確同意**：用 `prompts/personas.json` 的六位新角色（老周、老馮、小楷、阿湛、小蔡、老錢）取代 `party.js` 目前的六位（阿哲、小雯、Kevin、美玲姐、小宇、艾莉）。
- 先前「保留現有角色名稱、人設與關係，不要擅自改寫」的規定，對這次替換**不適用**。除此之外的其他規定仍然有效。
- 舊角色資料請保留在 git 歷史中，不要刪除歷史，也不要另存一份混在新檔案裡。

## 前提與限制
1. 目前已經是 `PARTY_MODE=sequential`，每個角色獨立呼叫、後面的人看得到前面的話。發言者選擇、話題狀態、收斂提示、重複偵測、逾時**已經存在**，不要重做，只在需要時調整。
2. 穩定性修改尚未 commit，也未通過實機驗收。**在它們被我確認並 commit 之前，不要修改 `party.js` 或任何程式檔。**
3. 「處理時發生錯誤」在 `index.js` 是所有功能共用的最後防線，且有測試檢查它。只改聚會那條路的降級行為，不要動共用的防線和相關測試。
4. 不要改動 OCR、翻譯、匯率、新聞等其他指令。（天氣功能已於 2026-11-17 依使用者決定整個移除，提交 `e429121`。）
5. 不提交金鑰；log 不記錄使用者對話內容。

## 階段 0：只盤點，不改任何檔案
1. 執行 `git status` 與 `git log -5 --oneline`，列出未 commit 的變更（檔名與簡述）。
2. 閱讀 `party.js`，回報：
   - 角色資料的結構與位置（行號範圍）、其他檔案如何引用角色名稱或 id。
   - 發言者選擇、話題狀態、重複偵測、逾時各自在哪裡、目前行為。
   - 模型呼叫的方式：用 Ollama 的哪個 API、傳了哪些 options，是否已關閉思考模式。
3. 閱讀 `package.json` 與 nodemon 設定，回報哪些路徑會觸發重啟。
4. 列出「新角色檔案」需要的格式與現有結構的差異（欄位對照表），以及哪些測試會因為角色改名而失敗。
5. 完成後停止，等我確認。

## 階段 1：版本控制準備（需我確認後才做）
1. 協助我驗收並 commit 穩定性修改（先列出驗收項目，由我實機測試）。
2. commit 完成後，開新分支（例如 `party-new-personas`）。
3. 把 zip 加進 `.gitignore`；把 `prompts/*.json`、`prompts/*.md` 加入 nodemon 的 ignore 或 watch 排除清單，避免改角色檔就重啟機器人（若要熱載入，另外實作重新載入機制）。

## 階段 2：角色與提示詞改由檔案載入
1. 從 `prompts/personas.json` 載入角色，從 `prompts/party_mode_prompt.md` 載入共用世界觀；`party.js` 內不再寫死角色文字。
2. 組裝函式：輸入「當輪角色、使用者名稱、最近對話、話題狀態、禁用片語、工具結果」，輸出 system prompt（共用世界觀 + 當輪角色卡）。
3. 更新受角色改名影響的測試與引用；新增組裝函式的測試（只含一位角色、佔位符都被替換、沒有工具結果時不殘留 `{tool_result}`）。
4. 載入失敗（檔案不存在、JSON 格式錯誤）時，要有清楚的錯誤訊息，並讓聚會模式回報無法啟動，而不是整個 bot 當機。

## 階段 3：新增的品質控制（只做目前沒有的）
1. 每個角色的字數範圍：依 `personas.json` 的 `length` 檢查，過長就截斷到最近的句尾。
2. 禁用片語：記錄每個角色最近 10 句，抽出重複的口頭禪與意象，放進 `banned_phrases` 注入提示詞。若已有重複偵測，沿用並擴充，不要另起爐灶。
3. 事實保護：本輪沒有 `tool_result` 時，若輸出含股價、匯率、天氣、新聞數字，就重新生成一次並提醒角色承認不知道。先用簡單規則（數字加關鍵字），並說明限制。
4. 聚會專用降級：模型呼叫失敗或輸出格式不符，重試一次；仍失敗時，只讓一位角色用簡短的話回應，不顯示「處理時發生錯誤」。

## 階段 4：取樣參數驗證（先驗證，再決定是否採用）
1. 目前程式沒有設定取樣參數。請先確認 Ollama 對 temperature、top_p、top_k、presence_penalty 是否都會生效（查文件並寫一個小腳本驗證，不要憑印象）。
2. 把確定會生效的參數放進設定檔，預設值參考 `personas.json` 的 `generation` 區塊。不會生效的就不要放，並說明原因。
3. 說明這些參數對聚會模式的預期影響，以及如何回復成原本的行為。

## 階段 5：離線模擬與驗證
1. 寫一支本機腳本，不經 LINE 模擬一段聚會對話，印出每個角色的輸出（可選擇接真實模型或 mock）。
2. 用 mock 模型補自動化測試：載入、組裝、截斷、禁用片語、事實保護、降級。
3. 提供手動驗證清單：角色語氣是否不同、有沒有互相接話、問股價時是否承認不知道、「結束聚會」是否正常、模型故障時是否降級而不是報錯。

## 回報格式
每個階段完成後，用繁體中文簡短回報：改了什麼檔案、怎麼測試、還有哪些風險，然後等我確認再進下一階段。
